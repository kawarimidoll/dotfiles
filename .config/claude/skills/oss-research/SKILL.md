# OSS Research

## 調査手段の使い分け

| 知りたいこと | 手段 | 隔離 |
|---|---|---|
| ライブラリの API・使用例 | context7 MCP を直接呼ぶ | 不要 |
| ドキュメントサイトの内容 | `ax <url> --md` | 不要 |
| 実装の詳細 | 下記の手順をサブエージェントに渡す | 必要 |

API とドキュメントは正確なシグネチャやフラグ名がそのまま欲しいので、要約を挟まず
メインコンテキストで読む。実装調査だけはソースの読み込み量が読めないため隔離する。

## 実装を読む手順

この節をそのまま Agent ツールのプロンプトに渡し、サブエージェントとして実行する。

### 1. ソースコードの取得

保存先: `/tmp/fetch-source/<repo>/`

```bash
# ref 指定あり（@tag または #branch）
git clone --depth 1 --branch <ref> "https://github.com/<owner>/<repo>.git" "/tmp/fetch-source/<repo>"

# ref 指定なし（デフォルトブランチ）
git clone --depth 1 "https://github.com/<owner>/<repo>.git" "/tmp/fetch-source/<repo>"
```

同名ディレクトリが既に存在する場合はそのまま再利用する。

タグ指定で clone に失敗した場合、`v` プレフィックスの有無を切り替えて再試行する。

### 2. 調査

- ディレクトリ構造を確認する
- 指示されたファイルやコードを読んで調査する
- 質問に答える

### 3. 報告

- 調査結果を簡潔に要約して返す
- 該当ファイルのパスと関連コードの要点を含める
